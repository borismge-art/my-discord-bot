# Discord persona bot — каркас

## Что тут есть
- `bot.py` — логика бота: помнит последние сообщения канала, отвечает от твоего имени через LLM, читает весь чат и сам решает, когда влезть, смотрит картинки, шлёт подходящие по ситуации гифки.
- `persona.md` — описание стиля + примеры диалогов. Редактируется отдельно от кода — сюда добавляй новые диалоги, ничего не трогая в bot.py.
- `gifs.txt` — список гифок. Формат строки: `URL | короткое описание (когда уместна)`. Описания нужны, чтобы бот понимал, какую гифку послать под ситуацию. Строки `#` игнорируются. Ссылки должны быть ПРЯМЫМИ на файл (отдавать image/gif) — страницы типа tenor.com/view/... и klipy.com/gifs/... не работают.
- `fix_gifs.py` — автопочинка ссылок: tenor.com/view/... заменяет на прямой gif (через og:image страницы), мёртвые (404/403, истёкшие Discord CDN) помечает «НЕ РАБОТАЕТ» — такие бот не шлёт. klipy.com не чинится автоматически (страницы под 403, их поиск отдаёт одну картинку на любой запрос) — только замена вручную. Перед записью делает бэкап gifs.txt.bak-fix. Запуск: `python fix_gifs.py`.
- `.env.example` — шаблон настроек. Скопируй в `.env` и впиши реальные значения, `.env` никуда не отправляй и не заливай в открытые репозитории.
- `requirements.txt` — зависимости.

## Настройка

1. Создай приложение и бота на https://discord.com/developers/applications, включи там **Message Content Intent** (Bot → Privileged Gateway Intents), скопируй токен бота.
2. `cp .env.example .env` и заполни:
   - `DISCORD_TOKEN` — токен из шага 1.
   - `LLM_API_KEY` и `LLM_BASE_URL` — данные твоего шлюза (base_url должен быть в формате openai-совместимого API, обычно заканчивается на `/v1`).
   - `LLM_MODEL` — точное имя модели так, как его ожидает шлюз (может отличаться от "Sonnet 5" из выпадающего списка — уточни у продавца/в доке шлюза, если запрос будет падать с ошибкой "model not found").
3. Установи зависимости:
   ```
   pip install -r requirements.txt
   ```
4. Запусти:
   ```
   python bot.py
   ```
5. Пригласи бота на сервер (OAuth2 URL Generator → scope `bot`, права как минимум "Read Messages/View Channels", "Send Messages", "Read Message History").

## Как это работает сейчас
- Бот отвечает на **тег** всегда (как раньше).
- **Новое: проактивный режим.** Без тега бот тоже читает чат: отправляет историю в модель со служебной инструкцией «отвечай только если уместно, иначе `%%SILENT%%`». Модель решила молчать — бот молчит (это пишется в `bot.log` как `SILENT`).
- **Новое: картинки.** Image-аттачменты скачиваются и уходят в модель (до `IMAGES_PER_REQUEST` последних на запрос, тяжелее `IMAGE_MAX_MB` МБ не качаются). Если шлюз упадёт на запросе с картинками — автоматический повтор тем же запросом без картинок.
- **Гифки по ситуации.** Модель видит пронумерованный список гифок с описаниями из `gifs.txt` и сама решает, послать ли какую-то: вставляет в ответ маркер `%%GIF:номер%%`. Гифка отправляется **вложением (файлом)** — бот скачивает её и грузит как attachment, поэтому в чате она встраивается как анимация, а не как ссылка/embed-карточка. Скачанное кэшируется в папке `gif_cache/` (повторная отправка — мгновенно). Если скачать не удалось или файл тяжелее `GIF_MAX_UPLOAD_MB` (лимит вложения без Nitro) — fallback: отправляет ссылку текстом. Работает и по тегу, и когда бот влезает сам.
- **Локальные гифки в `gifs_local/`.** В `gifs.txt` строка вида `gifs_local/имя.webp | описание` — это файл с диска, а не ссылка. Локальные надёжнее: чужие CDN умирают, а подписи Discord `?ex=...&hm=...` истекают за 24 часа. Discord анимирует `.webp` во вложениях, поэтому конвертировать в GIF не нужно — и нельзя переименовывать webp в `.gif`, иначе придёт статичный кадр. Если файл пропал, бот пишет в лог и молчит в чат: путь в чат никогда не отправляется, модели показываются только описания (без путей). Список того, что осталось доскачать руками, — в `gifs_local/README.md`. Как добавить свою: скопировать файл в `gifs_local/`, прописать строку в `gifs.txt` с описанием (по нему модель выбирает, когда послать).
- Если тег без текста — отправляется случайная гифка из `gifs.txt` (старое поведение).
- Битые ссылки (описание начинается с «НЕ РАБОТАЕТ») модели не показываются и не шлются. `fix_gifs.py` проверяет ссылки и помечает мёртвые; локальные файлы он проверяет по диску (не через HTTP) и сохраняет твои комментарии в шапке файла.
- `gifs.txt` перечитывается раз в минуту — правки подхватываются без рестарта бота.
- Берётся история последних `HISTORY_LIMIT` сообщений канала + `persona.md` как системный промпт.
- Антиспам: `COOLDOWN_SECONDS` между прямыми ответами; после автоответа — пауза `AUTO_COOLDOWN` сек; после «промолчал» — `SILENT_COOLDOWN` сек до следующей проверки. Сообщения короче `MIN_AUTO_LEN` символов без тега модель не дёргают.
- **Адресность ответов.** На тег бот знает, КТО именно его позвал, и получает служебную пометку с точным текстом сообщения — отвечает именно на него, а не дожёвывает чужие команды выше по чату (например, массовый роаст по команде другого человека). Ответ привязан reply'ем к сообщению. Тег, пришедший во время cooldown, не выбрасывается: бот отвечает на него сразу после cooldown.
- **Reply-контекст (кому отвечает человек).** Сообщения с reply-цитатой Discord пишутся в историю с пометкой `[в ответ ник: «цитата»]` — модель видит, КТО адресат ответа, и не путает адресата (раньше «синий ленин» отвечал borisbrat'у, а бот считал, что тот говорит с ним). Пометка срабатывает по `message.reference` (resolved → кэш → REST-фолбэк), форварды не считаются ответами. **Ответ reply-цитатой на сообщение бота = прямое обращение** (даже без пинга бота) — бот больше не «глухой» к ответам на свои реплики. Свои ответы бот пометкой не размечает — в persona сказано не копировать эту разметку.
- **Титул — только создателю и редко.** Полный титул «О великий...» — только `CREATOR_NAME` (по умолчанию `borisbrat`, меняется в `.env`) и максимум ~1 раз за разговор; в обычных ответах создателю — «борис»/«батя»/«шеф» или без обращения. «Повелитель»/«мой господин» — запрещены. Всем остальным титул не выдаётся никогда. Создателя бот никогда не троллит по чужой команде.
- **Игнор гифок (`GIF_IGNORE_USERS`).** Юзернеймы через запятую: их сообщения, состоящие ТОЛЬКО из гифок (ссылки klipy/tenor/giphy или вложения .gif/.mp4/.webm), пропускаются молча — без ответа, без траты токенов. Текст+гифка всё равно получает ответ (отвечает на текст). По умолчанию `kabanrustix`.
- **Рабочие теги людей.** Модель пишет в ответе `@юзернейм`, бот сам раскрывает его в дискорд-тег `<@id>`: кэш ник→id пополняется авторами всех сообщений и списком участников сервера при старте; если ника нет в кэше — доищется через REST `query_members` (работает без Server Members Intent). В системный промпт добавляется список юзернеймов сервера. `@everyone`/`@here` никогда не раскрываются.
- **Словарь кличек `aliases.txt`.** Формат: `кличка = username`. Клички раскрываются в рабочие теги и с `@`, и без него («доша», «@Ратчет», «@Я и Сталина съел» → тег alanderbrie/prosto_ratchet/sanek331). Перечитывается раз в минуту. Ростер в промпте подсказывает модели, каких кличек избегать. Кличка срабатывает только как целое слово («дощатый» не заденет «дошу»).
- **Модель не видит сырых `<@id>`.** Все упоминания во входящих сообщениях (и в собственных ответах бота) перед записью в историю заменяются на `@юзернейм`/`#канал`/`@роль` — иначе модель копирует формат `<@число>` и выдаёт битые (иногда выдуманные) id. На выходе дополнительная защита: галлюцинированный `<@id>` гуманизируется (реальный → тег, выдуманный → безобидный текст).
- **Картинки не раздувают запрос.** Image-аттачменты сжимаются перед отправкой (длинная сторона ≤ `IMAGE_MAX_PX`, JPEG q=`IMAGE_JPEG_Q`, анимация → первый кадр), иначе шлюз отвечает `413 Payload Too Large`.
- **Анти-заедание.** Ответ, похожий на один из 4 последних своих (`DUP_THRESHOLD`, 0..1), по тегу перегенерируется с указанием «не повторяйся», а в проактивном режиме просто проглатывается (лог `DUP-SILENT`). Если один и тот же вопрос в чате повторяют 2+ раз — модель получает служебную подсказку, что её берут на заедание, и троллит спрашивающих вместо очередного ответа по сути. Если перегенерация тоже дубль — берётся второй вариант (раньше отправлялся первый дубль как ни в чём не бывало).
- **Фильтр канцелярских отказов.** Если модель выдала отказ ассистента («Я не хочу обсуждать политические темы», «Как ИИ, я не могу...») короткой фразой — в момент отправки он подменяется репликой в характере (рандом из 4 вариантов). Настоящие содержательные ответы с упоминанием темы не трогаются. Причина: на провокационную тему модель уходит в канцелярит, фраза попадает в историю — и бот повторяет её на каждое «Привет».
- **Санитайзер утечек шлюза (`sanitize_gateway_reply`).** Шлюз (buytokens-прокси) иногда возвращает в `content` reasoning-мусор и ответы на ЧУЖИЕ запросы: обрывки размышлений («Wait, checking», «# Journal», «Похоже, пользователь...»), спецтокены `<｜begin▁of▁sentence｜>`, эхо системного промпта («Ты — Борис... # ЗАДАЧА»), JSON tool-call обёртки `{"name": "set_response", "arguments": {"text": "..."}}`. Чистка: (1) текст вынимается из JSON-обёртки; (2) мусор перед репликой отрезается по маркерам (`_LEAK_MARKERS`, ~35 паттернов, пополняется по мере новых утечек); (3) огрызки без кириллицы (обрывы вроде «'t Know what to do») отбрасываются; (4) если после чистки ответ изменился — один перезапрос. Маркеры делятся на волны: английские reasoning-зачины, эхо промпта, русский канцелярит модели.
- **Чистые гифки/картинки без текста и без тега** комментируются редко — с шансом `MEDIA_COMMENT_CHANCE` (0.25 = каждая четвёртая); остальные молча игнорируются.
- **Активности участников — в том числе чужие.** При ответе на тег бот видит, чем занят сам собеседник (игра, Spotify, стрим, кастомный статус). А если вопрос про ДРУГОГО человека («во что играет Андрюха?», «что он слушает», «кто во что задротит») — бот получает список активностей **всех участников сервера** вместе с их кличками из `aliases.txt`, поэтому сопоставляет «Андрюха» → `andrey_d_` и называет реальную игру (включая деталь вроде «Building Уолден»). Если активности не видно — боту прямо велено так и сказать, а не выдумывать игру. Требует **Presence Intent**: панель https://discord.com/developers/applications → приложение → Bot → Privileged Gateway Intents → «Presence Intent» → Save. Если intent не включён — бот сам запустится без активностей (в логе будет инструкция), ничего не сломается. Ключ `PRESENCES=0` в `.env` отключает фичу полностью.
  - **Прочёс участников (`MEMBER_SWEEP_INTERVAL`, по умолчанию 900 сек).** Без Members Intent кэш участников почти пуст (в тесте 3 из 51), а discord.py **отбрасывает** presence-события незнакомых людей (`PRESENCE_UPDATE referencing an unknown member ID: Discarding`) — именно поэтому раньше бот отвечал «не разобрал». Раз в `MEMBER_SWEEP_INTERVAL` бот прочёсывает сервер через `query_members` по префиксам `a-z`/`0-9`/`_`/`.` (это gateway-запрос, он не требует Members Intent, в отличие от `guild.chunk()`), заполняя кэш — 3 → 51 участник. Если спросить про активность сразу после старта, пока прочёс не прошёл, бот докачает кэш по месту (`ensure_activity_cache`). `ACTIVITY_MAX_MEMBERS` (25) ограничивает размер списка в промпте.
  - Members Intent включать НЕ нужно: панель его для этого бота запрещает (`PrivilegedIntentsRequired`), а прочёс закрывает задачу без него.
- **Память о людях (`people.jsonl`).** После каждого своего ответа (не чаще раза в `MEMORY_EXTRACT_INTERVAL` сек на канал) бот фоном прогоняет историю через модель-экстрактор и записывает интересные факты о людях в `people.jsonl` (формат: по одной JSON-записи `{"nick", "fact", "ts"}` на строку). Файл лежит в папке бота, его можно читать и править руками — бот подхватит правки (кэш по mtime+размеру). При ответе в промпт подмешивается блок `[ПАМЯТЬ]`: все факты про собеседника + последние ~15 общих (лимит `MEMORY_BLOCK_CHARS`). **Анти-дубль в два слоя:** (1) экстрактору показывается список уже сохранённых фактов про этих людей, чтобы он не переформулировал известное заново; (2) при записи факт сравнивается с уже имеющимися по тому же нику нечётко (`MEMORY_DUP_THRESHOLD`, difflib) — переформулировка одного факта отбрасывается. Запись атомарная (temp + rename), поэтому файл не «склеивается» при перезапуске бота. Потолок файла `MEMORY_MAX_ENTRIES` (старое вытесняется). Отключение: `MEMORY_ENABLED=0`.
- **Аватарка бота (Хоррор Масюня).** Своя аватарка кэшируется в `avatar_cache.png` и показывается модели (сжатая до `AVATAR_PX`) ТОЛЬКО когда спрашивают про внешность/аватарку/Масюню — на обычные сообщения токены не тратятся. В persona.md описан лор: Масюня питается страхом участников, сыта когда бот удачно троллит.

## Ключи .env для проактивного режима (у всех есть дефолты, можно не прописывать)
- `AUTO_REPLY=1` — проактивный режим включён. `AUTO_REPLY=0` — вернуть старое поведение «только по тегу».
- `AUTO_COOLDOWN=60` — мин. пауза между автоответами в одном канале, сек.
- `SILENT_COOLDOWN=15` — через сколько сек после «промолчал» можно проверить следующее сообщение, сек.
- `IMAGES_PER_REQUEST=3` — сколько последних картинок уходит в один запрос модели.
- `IMAGE_MAX_MB=8` — картинки тяжелее этого не скачиваются.
- `MIN_AUTO_LEN=3` — сообщения короче этого без тега игнорируются.

Расход токенов: в активном чате без тега — примерно один запрос в `SILENT_COOLDOWN` секунд (чаще модель просто отвечает SILENT и запросов нет, пока идёт пауза). Прямые ответы по тегу — как раньше.

## Что доделать завтра
- Добавить в `persona.md` новые диалоги, которые пришлёшь.
- Вставить реальные ссылки в `gifs.txt`.
- Понаблюдать за `bot.log`: строки `SILENT` показывают, где бот решил промолчать. Если молчит слишком часто/редко — подкрути `SILENT_COOLDOWN`, `AUTO_COOLDOWN` или текст служебной инструкции (`AUTO_SUFFIX` в `bot.py`).
- **Ротация `bot.log`.** Лог вращается сам: `bot.log` всегда текущий, раз в сутки (в полночь) он архивируется в `bot.<дата>.log`, хранится только 2 последних архива, всё старее удаляется автоматически. Ничего чистить руками не нужно.

## Для долгой работы без присмотра (на время армии)
- Запускай через `systemd`, `pm2` или хотя бы `screen`/`tmux`, чтобы бот поднимался заново при падении/перезагрузке сервера.
- Проверь, что VPS/хост будет оплачен и доступен весь срок.
- Если шлюз с ключом перестанет отвечать — бот будет писать "чёт я завис, спроси попозже" вместо падения, но стоит иногда проверять `bot.log`.
